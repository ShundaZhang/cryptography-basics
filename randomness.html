01 / FIELD NOTES

Entropy feeds deterministic expansion

A DRBG can generate many bits without generating new physical entropy for every bit.

A noise source plus conditioning and health tests supplies seed material. A cryptographic DRBG evolves state and produces pseudorandom output; its security depends on entropy, algorithm and state protection. SP 800-90B addresses entropy sources, 90A specifies DRBG mechanisms, and 90C combines them into RBG constructions. Statistical “random-looking” output alone does not establish unpredictability.

H_min(X) = −log₂(max_x Pr[X=x]) A 256-bit output does not imply a 256-bit unpredictable seed

Random and unique are not synonyms

The required property comes from the construction.

03 / FIELD NOTES

Use the OS CSPRNG through a supported API

For Python, secrets is the intended interface for secret values.

import secrets
key = secrets.token_bytes(32)
token = secrets.token_urlsafe(32)
index = secrets.randbelow(10)  # unbiased range sampling

Do not seed a PRNG with time or use random / Math.random for keys. Avoid reducing a random byte modulo a range when it introduces bias. Embedded systems and early boot need an explicit entropy-ready design; forked processes, snapshots and restored generator state need implementation support. Hardware RNG instructions are inputs or interfaces to evaluate, not a universal proof of entropy.
