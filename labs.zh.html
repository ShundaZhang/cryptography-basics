实验 / FIELD GUIDE

观察安全属性
验证失败条件

四个使用 Web Cryptography API 的本地浏览器实验。输入和临时密钥留在当前页面，不上传或保存实验数据；需要 HTTPS 或 localhost。

HashAEAD签名Nonce 复用
01 / DIGEST

改变输入，比较两个摘要

Hash 是确定性的；摘要发生变化不证明谁创建了数据。

就绪 — 选择实验

实验比较 SHA-256 摘要并统计改变的输出位数。约一半是常见现象，而非每一对输入的保证或安全证明。“hello” 同时提供已知答案检查。

对应资料：FIPS 180-4：SHA-2 ↗ · W3C Web Cryptography API ↗

02 / AEAD

认证成功后才释放明文

AES-GCM 认证密文和 AAD，但不替应用记录重放历史。

就绪 — 选择实验

每条新记录在本小实验中使用新生成的密钥和随机 96 位 Nonce。后续操作针对已密封记录；编辑输入后须创建新记录。实际系统需要密钥使用上限、持续唯一的 Nonce 和协议重放处理。

对应资料：SP 800-38D：GCM ↗ · W3C Web Cryptography API ↗

03 / SIGNATURE

签名把字节绑定到密钥

数学验签不确定密钥是否属于可信身份。

就绪 — 选择实验

浏览器生成临时 ECDSA P-256 密钥对并配合 SHA-256 签名。仅展示公钥与签名字节；私钥不可导出，关闭页面后丢弃。本实验不创建证书，也不声明人的身份。

对应资料：W3C Web Cryptography API ↗ · Boneh–Shoup：应用密码学教材 ↗

04 / MISUSE

Nonce 重复，密钥流重复

用两条短示例消息故意展示一次本地误用。

就绪 — 选择实验

在两条消息重叠长度内，AES-GCM 重复 key/nonce 导致 CTR 密钥流重复，暴露 C₁ XOR C₂ = P₁ XOR P₂。比较时排除最后 16 字节认证 Tag。这展示明文间关系，并非完整 GCM 伪造实验。勿用于真实数据。

对应资料：SP 800-38D：GCM ↗
