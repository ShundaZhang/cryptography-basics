AES 与流密码的接口不同

AES 对一个 16 字节块执行带密钥的可逆变换；工作模式定义如何用它处理消息或存储单元。

算法密钥长度分组长度轮数
AES-128128 位128 位10
AES-192192 位128 位12
AES-256256 位128 位14

ChaCha20 是直接产生密钥流的流密码。AES 提供正向和逆向置换；CTR 等模式通过多次调用正向 AES 来产生密钥流。

对应资料：FIPS 197：AES ↗ · RFC 8439：ChaCha20-Poly1305 ↗ · Boneh–Shoup：应用密码学教材 ↗

02 / FIELD NOTES

AES 加密与解密

沿着密钥扩展、可逆的轮变换和逆向解密，追踪 16 字节状态。

AES 按列把分组放进 4×4 字节矩阵，state[row,col] = input[4·col+row]，最前面 4 字节填满第一列。KeyExpansion 把主密钥拆成 32 位字，扩展出 Nr+1 个 16 字节轮密钥。每隔 Nk 个字，先用 RotWord 循环移位、SubWord 逐字节查 S 盒，再异或轮常量 Rcon，最后与前推 Nk 个位置的字异或。AES-256 还在每组八个字的中间额外执行 SubWord。这里 Nk 为 4、6 或 8，Nr 为轮数。

AES Encrypt state ← AddRoundKey(input, RK[0]) for r = 1…Nr−1: state ← SubBytes → ShiftRows → MixColumns → AddRoundKey(RK[r]) output ← SubBytes → ShiftRows → AddRoundKey(RK[Nr]) AES Decrypt (inverse cipher) state ← AddRoundKey(ciphertext, RK[Nr]) for r = Nr−1…1: state ← InvShiftRows → InvSubBytes → AddRoundKey(RK[r]) → InvMixColumns plaintext ← InvShiftRows → InvSubBytes → AddRoundKey(RK[0])

每个箭头都对当前状态继续运算。逆密码使用相同的扩展轮密钥，顺序反过来；正向末轮及相应的逆向边界省去列混合。

SubBytes

S 盒先在 GF(2⁸) 中取乘法逆元（此步规定 0 映射到 0），再做仿射变换。例如 0x53 变为 0xed。解密时 InvSubBytes 使用逆 S 盒。

ShiftRows

字节仍在原来的行，但可能换到另一列。多轮交替执行移行和混列后，一个字节的变化会扩散到其他列。InvShiftRows 向右移动相同的距离。

MixColumns

每列在 GF(2⁸) 中乘同一个可逆矩阵，域的模多项式为 x⁸+x⁴+x³+x+1。首个输出字节是 (02·a₀) ⊕ (03·a₁) ⊕ a₂ ⊕ a₃，系数为十六进制；其余各行使用这些系数的循环移位。InvMixColumns 使用逆矩阵。

AddRoundKey

异或再执行一次就能还原。第一轮开始前先做一次轮密钥加；末轮仍做轮密钥加，并跳过 MixColumns。

03 / FIELD NOTES

AES 模式对照

底层都使用 AES，模式的输入和分组组织方式决定了各自的安全属性。

模式公开输入长度处理模式特点
ECB无整块独立加密泄露重复块
CBC不可预测 IV整块密文链接，仅机密性
CTR计数器块不重复可截取末块密钥流可并行生成密钥流，仅机密性
CFB不可预测 IV按段对齐密文反馈，仅机密性
OFB唯一 IV可截取末块密钥流密钥流反馈，仅机密性
GCM唯一 Nonce可截取末块密钥流带 Tag 和 AAD 的认证加密
XTS数据单元编号密文窃取等长的存储机密性

下文 E_K、D_K 表示密钥 K 下的 AES 正向、逆向置换，P[i]、C[i] 是明文和密文块或段，⊕ 表示异或，|| 表示比特串拼接，MSB_n / LSB_n 取前／后 n 位。除特别说明外，块编号从 1 开始。图采用 Wikimedia Commons 原图，各模式下方另附技术规范。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗ · SP 800-38D：GCM ↗ · SP 800-38E：XTS-AES ↗

04 / FIELD NOTES

ECB · 电子密码本模式

每个明文块独立送入同一把密钥下的 AES。

Encrypt: C[i] = E_K(P[i]) Decrypt: P[i] = D_K(C[i])

模式输入由完整的 16 字节块组成。加解密都可并行。同一密钥下，任意位置的相同明文块都会得到相同密文块，重复字段或图像轮廓会留下可识别的模式。

该模式没有 IV 和认证，攻击者还可以重排或替换整个块。ECB 有助于理解单块测试向量，普通消息加密应避免使用。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗

05 / FIELD NOTES

CBC · 密码分组链接模式

下一个明文块先与前一个密文块异或，再送入 AES。首块使用 IV。

C[0] = IV Encrypt: C[i] = E_K(P[i] ⊕ C[i−1]) Decrypt: P[i] = D_K(C[i]) ⊕ C[i−1]

使用新鲜、不可预测的 16 字节 IV。IV 可以公开，但需要完整性保护。CBC 处理整块；协议可选 PKCS#7，补 N 字节时每个字节值都是 N，原文恰好对齐时仍补一个完整块。填充规则由协议指定。

加密须等待 C[i−1]；拿到各密文块后，解密可并行。修改 C[i−1] 可以翻转 P[i] 的指定比特，泄露填充错误还可能形成填充预言机。旧协议需要先认证记录，再向调用方暴露明文或填充结果。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗

06 / FIELD NOTES

CTR · 计数器模式

加密一系列互不重复的计数器块，得到密钥流。

S[i] = E_K(T[i]) Encrypt: C[i] = P[i] ⊕ MSB_len(P[i])(S[i]) Decrypt: P[i] = C[i] ⊕ MSB_len(C[i])(S[i])

双方都调用 AES 加密。末尾不满一块时，只取等长的密钥流前缀。计数器布局和字节序由协议规定。各 AES 调用互相独立，已知块编号即可并行处理或随机访问。

同一密钥下，所有消息的完整计数器块 T[i] 都必须唯一，要防止范围重叠和回绕。重复时，重叠字节满足 C ⊕ C′ = P ⊕ P′。单独使用 CTR 时，翻转密文的一位也会翻转明文对应的一位。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗

07 / FIELD NOTES

CFB · 密文反馈模式

加密反馈寄存器，再把密文移入该寄存器。

R[1] = IV # 128-bit register S[i] = MSB_s(E_K(R[i])) Encrypt: C[i] = P[i] ⊕ S[i] Decrypt: P[i] = C[i] ⊕ S[i] R[i+1] = LSB_(128−s)(R[i]) || C[i]

段长 s 是模式参数，例如 8 位或 128 位。CFB-128 的寄存器更新简化为 R[i+1] = C[i]。输入按 s 位段处理，段对齐时无需分组填充。IV 是不可预测的 16 字节值。

加解密都调用 AES 加密，解密时反馈的也仍是密文。传输错误会影响当前明文段，并可能在错误密文尚未移出寄存器时继续传播。CFB 仅提供机密性。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗

08 / FIELD NOTES

OFB · 输出反馈模式

把 AES 输出本身送回下一轮，明文和密文均不进入反馈链。

O[0] = IV O[i] = E_K(O[i−1]) Encrypt: C[i] = P[i] ⊕ MSB_len(P[i])(O[i]) Decrypt: P[i] = C[i] ⊕ MSB_len(C[i])(O[i])

同一密钥下使用唯一的 16 字节 IV，并遵循规范的 IV 生成要求。加解密都调用 AES 加密。末块与 CTR 一样可截取等长密钥流，但 OFB 的密钥流块必须依次生成。

复用 IV 会重复密钥流。翻转密文的一位会翻转明文对应位，后续密钥流块照常生成。OFB 不提供认证。

对应资料：SP 800-38A：ECB、CBC、CFB、OFB 与 CTR ↗

09 / FIELD NOTES

GCM · 伽罗瓦／计数器模式

CTR 加密明文，GHASH 把密文和关联数据绑定到认证标签。

H = E_K(0^128) J0 = IV || 0^31 || 1 # 96-bit IV path C = GCTR_K(inc32(J0), P) # starts at the next counter X = pad128(AAD) || pad128(C) || len64(AAD) || len64(C) S = GHASH_H(X) Tag = MSB_t(E_K(J0) ⊕ S) Open: recompute and verify Tag from IV, AAD and C on failure return FAIL; on success release GCTR_K(inc32(J0), C)

pad128 只补达到分组边界所需的零比特；len64 将原始比特长度编码为 64 位整数。GHASH 从零开始，用 GCM 多项式 x¹²⁸+x⁷+x²+x+1 在 GF(2¹²⁸) 中迭代 Y ← (Y ⊕ X[i]) · H。末尾两个长度绑定 AAD 与密文的分界。Tag 的 AES 掩码用 J0，数据加密从 inc32(J0) 开始。

inc32 递增低 32 位；GCTR 按需截取末块密钥流。公式展示常用的 96 位 IV 路径；规范允许的其他长度需用 GHASH 推导 J0，图中也画出了该分支。Tag 长度和密钥用量按协议规定，认证成功后才释放明文。同一密钥下复用 IV 会泄露明文间的关系，并可能使攻击者伪造 Tag。

对应资料：SP 800-38D：GCM ↗

10 / FIELD NOTES

XTS · 带密文窃取的 XEX 可调分组模式

由数据单元编号和块索引派生 tweak，使密文与存储位置相关。

T[0] = E_K2(Encode128(data_unit_number)) T[j] = α^j · T[0] in the XTS field XEX_Encrypt(P, T) = E_K1(P ⊕ T) ⊕ T XEX_Decrypt(C, T) = D_K1(C ⊕ T) ⊕ T Partial tail of r bits, with last full block index j: CC = XEX_Encrypt(P[j], T[j]) C_tail = MSB_r(CC) C[j] = XEX_Encrypt(P_tail || LSB_(128−r)(CC), T[j+1]) Decrypt the tail pair: PP = XEX_Decrypt(C[j], T[j+1]) P_tail = MSB_r(PP) P[j] = XEX_Decrypt(C_tail || LSB_(128−r)(PP), T[j])

K1 与 K2 是两把等长、相互独立的密钥。XTS-AES-128 和 XTS-AES-256 的合计密钥材料分别为 256 位和 512 位。T[j] 在 GF(2¹²⁸) 中乘 α 的幂，字节及比特表示须遵守 XTS 约定。对齐的数据单元用 XEX 独立处理各块。

原图展示整块路径。密文窃取从临时密文 CC 中借出 r 位给短尾，再用下一个 tweak 加密拼成的整块。数据单元长度保持不变；最后的整块与短块按存储格式规定的顺序存放。一个数据单元至少包含一个整块，SP 800-38E 将其上限设为 2²⁰ 个 AES 块。

数据单元编号是位置参数，覆盖写入同一扇区时可重复。同一位置用同一密钥时，对比快照可以识别未变的数据。XTS 没有认证标签，也不防重放；存储系统需要额外机制来保证完整性或发现回滚。

对应资料：SP 800-38E：XTS-AES ↗

11 / FIELD NOTES

AEAD 认证密文和可见上下文

遵守模式定义的 Nonce 和 Tag 要求。

(ciphertext, tag) = Seal(key, nonce, plaintext, associated_data) plaintext or FAIL = Open(key, nonce, ciphertext, tag, associated_data)

AES-GCM 与 ChaCha20-Poly1305 结合加密和认证。关联数据可见但经过认证，可绑定版本、租户、内容类型或序号。接收方必须提供相同关联数据，并在使用明文前拒绝认证失败。

对应资料：SP 800-38D：GCM ↗ · RFC 8439：ChaCha20-Poly1305 ↗ · Python cryptography：AEAD 接口 ↗

12 / FIELD NOTES

唯一性是生命周期问题

随机 Nonce 不能自动解决重启与并发。

AES-GCM 不应在相同密钥下复用 Nonce。96 位 Nonce 是常见的高效选择，但仍受规范上限约束。ChaCha20-Poly1305 也要求唯一性。计数器分配要处理并发、崩溃和 VM 快照；随机分配要计算碰撞预算。恢复旧 key/nonce 状态时，密钥轮换本身也不能解决问题。

C1 = P1 XOR S C2 = P2 XOR S C1 XOR C2 = P1 XOR P2 # if the same keystream S is reused
真实性不等于防重放

未修改的认证记录可以验证两次。协议序号或请求状态需要另行跟踪。XTS 磁盘加密解决另一类问题，不提供 AEAD 式数据认证。

对应资料：SP 800-38D：GCM ↗ · RFC 8439：ChaCha20-Poly1305 ↗

13 / FIELD NOTES

一个有用的实现练习

既验证正确往返，也验证失败行为。

  • 加密一条记录，分别修改密文、Tag 与 AAD；每个修改后的记录都应认证失败。
  • 写清 Nonce 分配如何在重启和多个写入者之间保持唯一。
  • 按所选算法及协议设置记录大小和密钥使用预算，不设想无限使用寿命。
