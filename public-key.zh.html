01 / FIELD NOTES

三种操作，三类安全目标

密钥对不是可随意替换的 encrypt/sign 接口。

操作公开输入秘密输入 / 结果
公钥加密接收者加密公钥接收者私钥恢复明文
DH / KEM 密钥建立DH 公共份额，或封装公钥 / 密文私有输入产生共享密钥材料；KDF 派生用途密钥
数字签名验证公钥 + 消息 + 签名签名私钥产生签名，不产生秘密消息

RSA-OAEP 是加密方案；RSA-PSS 是签名方案。原始模幂既不是安全消息加密，也不是完整签名方案。X25519 用于 DH，Ed25519 用于签名，尽管两者的曲线数学相关。

对应资料：RFC 8017：PKCS #1 ↗ · RFC 7748：X25519 / X448 ↗ · RFC 8032：EdDSA ↗

02 / FIELD NOTES

用一个小例子理解协商

以下数字故意很小，只用于教学。

p = 23, g = 5 Alice: a = 6, A = g^a mod p = 8 Bob: b = 15, B = g^b mod p = 19 Alice: B^a mod p = 2 Bob: A^b mod p = 2

真实 DH 使用经过审查的群，并按要求校验公开输入。裸 DH 不认证对端：主动中间人可与双方分别协商秘密。应认证协商过程，并绑定角色和转录。临时密钥协商可在协议假设下，抵御之后长期密钥泄漏对历史会话的影响。

对应资料：Diffie–Hellman：New Directions in Cryptography ↗ · RFC 7748：X25519 / X448 ↗ · RFC 8446：TLS 1.3 ↗

03 / FIELD NOTES

签名依赖编码、Nonce 处理与身份

ECDSA、EdDSA 与 RSA-PSS 都有各自规则。

ECDSA 要求安全地产生每条消息的标量；复用或偏置可泄漏私钥。确定性生成是一种规定好的方案，不意味着可以自创 Nonce 规则。EdDSA 有自己的确定性设计；Hash、prehash、context 变体必须严格匹配。签署规定的表示并进行域分离，使用经过认证的公钥及算法约束验证。

签名不是“用私钥加密”

验签认证的是某个密钥下的签署字节。机密性、证书信任、授权和重放检查是不同问题。

对应资料：RFC 8032：EdDSA ↗ · RFC 8017：PKCS #1 ↗ · Boneh–Shoup：应用密码学教材 ↗

04 / FIELD NOTES

公钥需要信任路径

证书通过受策略约束的信任链连接名称和密钥。

证书链不能仅因各个签名数学有效就被接受。应检查选定信任锚、约束、有效期、用途、算法策略和撤销处理；TLS 还需核对预期服务名。Pinning 与原始公钥采用不同的登记和轮换模型。失去信任库控制可破坏原本正确的密码机制。

对应资料：RFC 8446：TLS 1.3 ↗ · SP 800-57 Part 1 Rev. 5：密钥管理 ↗
