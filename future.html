01 / FIELD NOTES

Quantum threats change public-key assumptions

PQC runs on classical hardware; it is not quantum communication.

A sufficiently capable fault-tolerant quantum computer running Shor’s algorithm threatens factoring and discrete-log systems, including RSA and common DH/ECC. Grover-style generic search changes symmetric-key and preimage work factors under an idealized model; practical costs and hash collision analysis differ. Do not apply one “halve every security bit” rule to every primitive.

StandardRoleFamily / status
FIPS 203 / ML-KEMKey encapsulationModule-lattice; published 2024
FIPS 204 / ML-DSADigital signaturesModule-lattice; published 2024
FIPS 205 / SLH-DSADigital signaturesStateless hash-based; published 2024

ML-KEM establishes a shared secret through encapsulation/decapsulation; it does not directly encrypt a file or authenticate a sender. Pair it with a defined KDF/AEAD protocol. Other selected or candidate schemes have separate standardization status; consult NIST rather than treating selection as publication.

02 / FIELD NOTES

Migration starts with data lifetime and inventory

Harvest-now-decrypt-later matters before a cryptographically relevant quantum machine exists.

Classify long-lived confidentiality needs and signature-verification lifetimes. Inventory certificates, KEM/DH uses, HSM firmware, wire formats and update mechanisms. Measure larger keys/signatures/ciphertexts, latency, memory and failure handling. Hybrid agreement uses a defined combiner; informal concatenation or fallback can defeat the intended property. RFC 10024, published August 2026, specifies TLS 1.3 ECDHE–ML-KEM groups including X25519MLKEM768. That upgrade protects agreement; certificate signatures remain a separate migration track.
