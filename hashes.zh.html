01 / FIELD NOTES

三种抗攻击属性

以下是理想 n 位摘要的通用经典工作量估计。

属性攻击者任务通用成本
原像给定 y，寻找满足 H(x)=y 的 x≈ 2^n
第二原像给定 x，寻找同 Hash 的另一 x′≈ 2^n
碰撞自选任意不同 x、x′ 使 Hash 相同≈ 2^(n/2)

SHA-256 / SHA-512 属于 SHA-2；SHA-3 使用不同的海绵结构，SHAKE 是可扩展输出函数。Hash 是确定性且通常公开的。若攻击者可同时替换文件及公布的 Hash，比较仍可成功。MD5 与 SHA-1 是碰撞安全被破坏的历史例子，不应用于新的签名完整性设计。

对应资料：FIPS 180-4：SHA-2 ↗ · FIPS 202：SHA-3 / SHAKE ↗ · Boneh–Shoup：应用密码学教材 ↗

02 / FIELD NOTES

HMAC 加入共享认证秘密

普通 Hash 不能识别消息由谁创建。

tag = HMAC(key, encoded_message) accept only if constant_time_compare(expected_tag, received_tag)

HMAC 使用规定的嵌套带密钥 Hash 构造。不要替换为 H(secret || message)：Merkle–Damgård Hash 在这种构造下可出现长度扩展。每位 MAC 密钥持有者都可生成有效 Tag，因此 HMAC 不提供公开验证，也不区分这些持有者。跨协议使用不同密钥与域标签。

对应资料：RFC 2104：HMAC ↗

03 / FIELD NOTES

HKDF 提取并扩展密钥材料

KDF 整理熵，不会从易猜口令中创造熵。

PRK = HKDF-Extract(salt, input_key_material) K_enc = HKDF-Expand(PRK, "protocol-v1/encryption", length) K_auth = HKDF-Expand(PRK, "protocol-v1/authentication", length)

Salt 与 context/info 的作用不同。Salt 不必保密；info 用于区分用途并绑定上下文。遵守协议规定的标签和长度。密钥建立输出通常应先经过指定 KDF，再用作 AEAD 密钥。

对应资料：RFC 5869：HKDF ↗

04 / FIELD NOTES

口令存储有意消耗时间与内存

随机 Salt 防止跨用户复用预计算，不防止针对单个用户猜测。

使用 Argon2id 等口令 Hash 方案，并校准内存 / 时间参数和唯一 Salt。保存算法版本及参数以便升级。快速 SHA-256 即使加 Salt，仍给离线攻击者提供便宜的猜测循环。HKDF 不是口令强化函数。Pepper 是额外托管秘密，会引入独立的恢复与轮换问题。

对应资料：RFC 9106：Argon2 ↗ · RFC 5869：HKDF ↗
